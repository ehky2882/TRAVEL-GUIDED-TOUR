### ⚠️ A defect of my own, caught while building the place

**All seven pin heroes shipped as `…/images//file.webp`** — a double slash, because the
`--image-base` I passed to `make-link-pin.py` already ended in one and the tool appends another.

**Nothing was broken**: both forms return **200** (GitHub Pages collapses the double slash), and the
live bytes were hash-verified either way. But it was inconsistent with the other 276 pins, and
`URLCache` keys on the exact URL string, so the two forms would cache as two separate entries.
Corrected to the single slash in the same PR.

**The durable point: pass `--image-base` WITHOUT a trailing slash**, and check a generated
`heroImageURL` against an existing pin's before committing a batch — the tool does not normalise it
and no check in the pipeline flags it, because every URL still resolves.
