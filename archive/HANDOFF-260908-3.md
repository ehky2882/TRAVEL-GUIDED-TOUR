## What was built, and why it is two files

The two audiences are different, so conflating them into one document would have served neither.

**`docs/partner-onboarding.md` — for the human.** Accounts, repository access, Claude Code on the
web, the link-pin job as *what to collect* and *what to type*, a troubleshooting table and a
glossary. **Claude Code on the web is the recommended surface and the desktop app the alternative;
the terminal path is deliberately not offered at all** — the owner does not use Terminal and neither
will his partner, so presenting it as an option only invites a failure mode nobody can support.

**`.claude/skills/atlas-upload/SKILL.md` — for his Claude.** Loaded by saying *"use the atlas-upload
skill"*. It routes the four jobs and carries the link-pin flow in full, then points at
`docs/link-pin-runbook.md` and `CLAUDE.md` for everything else rather than restating them — a second
copy of the pipeline would drift from the first within a month.

This is the repository's **first `.claude/skills/` entry**. Project skills are discovered
automatically in a session with the repo attached, so nothing has to be installed on his side; the
one sentence is the whole interface.

## The guardrails that went into the skill

Chosen for what a novice cannot be expected to know, and every one already paid for here:

- keep the pin JSON out of the conversation — a batch of 20 pasted into chat is ~21k tokens **on
  every later turn**, not once
- pins go in `linkPins` and never in `tours` — the silent whole-catalog decode failure
- the handle suffix on hero filenames, or a pin overwrites the Atlas tour of the same subject
- a photo correction is a **new filename**, never bytes swapped at a live URL (PR #567)
- `--pins` for a pin batch, `--maker` for a city — not interchangeable, because a creator handle
  collides with city codes as a substring
- `check-coordinates.py` before a city drop, including **the BIAS line**, not just the gross list
- the three ways a check that could not run returns something that reads like a pass

It also sets the posture, which matters more than any single rule: run the commands yourself,
explain in plain English, never print JSON at him, and hand anything code-shaped back to the owner.

⚠️ **The 62/62 reading is the bare-container one.** Session 149 records that
`make-link-pin.py --selftest` reports **71/71 with Pillow installed** and 62/62 without — *"which
reads as a pass and is not one"*. It was not re-run with Pillow here. Nothing in this session's
change depends on the image path, but a session wiring a real batch should install Pillow first and
expect 71.
