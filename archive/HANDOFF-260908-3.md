## Three things that would have shipped broken

1. 🔴 **A naive Plus Code recovery put a pin in rural Pennsylvania.** `P272+V9 New York`
   recovered to longitude **−74.999**, a degree out, because taking the prefix from the
   reference point fails when the reference sits near a cell boundary. Fixed with the real
   OLC **`recoverNearest`** rule. `openlocationcode` will not build on this container, so
   the decoder is hand-rolled and **self-tests on every run** against three published
   vectors (including this repo's own Eiffel vector), a recover-nearest property and an
   encode/decode round trip — and refuses to run if any fails.

2. 🔴 **A wrong geocode that reverse-verification would have confirmed.** `Park Avenue
   Plaza, New York` matched **a village near Corning, 250 km upstate** — a real place, so
   a reverse lookup agrees with it. Only a **bounding box for the city the caption names**
   caught it. That check is now run on every derived coordinate: 27/27 in box.

3. 🔴 **Three Met pins would have been a 4-deep stack.** Geocoding put all three on one
   identical coordinate, where the existing pin `The Met's Design Flaw` already sits —
   4 entries against `TourSetMap.maxStacked = 3`, so one is dropped by `prefix()` and
   becomes permanently unreachable, silently. The Met is **already a place** 17 m away, so
   the three are placed on the place's own point and added to its `tourIds` (2 → 5) and
   collapse into the place pin. Precedent: Eastern State's third member (#743).
