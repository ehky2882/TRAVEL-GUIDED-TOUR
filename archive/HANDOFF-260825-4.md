## 3. 🔴 The one thing worth remembering: the shared sort is STABLE, and that is load-bearing

`Array.sorted` is **not** stable. A place's tours are almost always published in one city batch, so their `createdAt` ties **exactly** — 22 of the 24 places when the place layer shipped (`PlaceRankingTests` documents this). `Place.ranked` breaks those ties deliberately: the single-stop tour before the walk that merely *starts* at the same spot, then title.

An unstable sort would have discarded that the moment the page ordered by its own default. So `AtlasTourSort.sorted` decorates with the incoming index and falls through to it whenever the criterion cannot separate two tours — `compare(...)` returns `Bool?`, and `nil` means "these are tied". Under **Newest** the place page therefore reproduces `Place.ranked` byte for byte, tiebreaks included. The maker feed gains the same property: ties keep catalog order rather than an arbitrary one.

`.distance` with no location fix returns `nil` for every pair, so the list is left exactly as it came instead of put in a meaningless order — the same behaviour the maker page had, expressed once.

`AtlasTourSortTests` (11 cases) pins: stability in **both** directions, each criterion both ways, undated-sorts-last in both directions, no-fix-leaves-order-alone, the default directions, and the label vocabulary.

## 4. ⚠️ Traps hit, and one avoided

- **The hero must read the ranked order, never the sorted one.** `heroImageURL` and the carousel's category fallback were `tours.first?…`; with a sort control that would have **changed the photograph at the top of the page** when the reader sorted by name. There are now two properties: `rankedTours` (identity — hero, category) and `tours` (the displayed list).
- **Measure a grid BEFORE its inset.** The `GeometryReader` background has to sit under the `.padding(.horizontal, .lg)`, not over it, or it reports the padded width and every tile comes out 16pt too wide. `MakerView` gets away with no comment because its padding is applied by a parent.
- **`main` moved mid-session** (#599, docs only) and was merged in before cutting 119 — the 1.1 (92) lesson. Check immediately before every build, not at branch creation.

## 5. ⚠️ Two earlier decisions retired ON PURPOSE — do not restore them

Both were deliberate calls recorded in code comments, and both were reversed by the owner on 2026-08-25. The note explaining this now lives **at the row itself**, so nobody reinstates them from a stale comment:

1. **The brass count.** `N TOURS AVAILABLE` in `AtlasColors.accent`, kept as a deliberate divergence on 2026-08-18 *"because the count of tours is why a place page exists"*. It is `tourCountText` in `tertiaryText` now.
2. **The stated order.** `NEWEST FIRST` as text, on the grounds that *"a sort control would be a promise the app cannot keep"*. It can: name, duration, distance and date need no usage data — only a *popularity* sort would, and none is offered.

`PlaceView`'s type doc comment was updated too; it previously claimed the brass count was "the one deliberate divergence".
