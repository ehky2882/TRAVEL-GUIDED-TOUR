## 🔴 The Oedo pin was sited on the wrong subject, and the near-miss is the lesson

Atlas carries **two** tours at that site — *Oedo Antique Market* and *Tokyo International Forum* —
**94 m apart**, because the market is held in the Forum's plaza. The proximity sweep named the Forum
as nearest (29 m) and the pin was sited there. **The video is about the market.**

It was caught only because `oedo-antique-market_hero.webp` was already taken when the hero was being
renamed. **A sweep that stops at "nearest tour" gets this class wrong every time** — the nearest
marker is not necessarily the same subject.

Five more pins land near an Atlas tour and are genuinely *different* subjects: Kichi Kichi 30 m from
*Cavalier*, Gokan 75 m from the Duddell Street Steps, 28 Liberty 130 m from Federal Hall, the Hess
Triangle 46 m from the Stonewall National Monument, the Sistine Chapel 214 m from St Peter's Square.

## ⚠️ Every pin hero now carries its creator's handle — new convention, NOT yet in the generator

`green-wood-cemetery-mylestoes_hero.webp`, not `green-wood-cemetery_hero.webp`. A bare subject slug
collides with the Atlas tour of the same subject, and an overwritten hero at a live URL is the
Thyssen bug — which since #567 a phone that already downloaded the tour would never see corrected.
`make-link-pin.py` still emits **caption-derived** slugs in batch mode (`--slug` is ignored when
there is more than one row), so the renaming was done by hand. **Fold the rule into the generator
before the next batch.**

## ⚠️ `createdAt` is served on ZERO tours, and it silently disables four sort controls

The live RPC returns `createdAt` on **0 of 1513** tours. `Tours.json` has it on 1476/1512 (36 missing:
35 SFO + 1 London). This is a **documented KNOWN_GAP** in `scripts/check-catalog-contract.py`, not a
new regression — but its consequences are wider than that note says now:

- `Place.ranked` sorts newest-first and has no dates, so it falls through to its tiebreaks.
- The maker page's **Newest / Oldest** sort does nothing on a device.
- `.dateAdded` in `AtlasTourSort`, shipped to place and list pages in #600/#601, is inert.

**🔴 DO NOT "fix" by adding `tours.created_at` to `get_catalog`** — that column is `default now()` and
holds seed time, so most of the catalogue shares 2026-06-27. It would look fixed and rank wrongly.
Real fix, in that order: teach `seed_from_toursjson.py` to carry the authored date, backfill the 36
missing ones from git history, *then* add the key.

## Mechanics that worked, and one that did not

- **All three oEmbed endpoints are reachable from a web container** — TikTok, YouTube, and Instagram
  via `graph.facebook.com`, all HTTP 200 unauthenticated.
- **Pillow is NOT installed in a fresh web container** and the generator cannot crop a hero without it.
  `pip install Pillow` — one line, but it blocks everything.
- **`scripts/upload-images.py` requires the `gh` CLI, which a web session does not have.** Fell back to
  git plumbing: blobless fetch → temp `GIT_INDEX_FILE` → `hash-object -w` → `update-index --cacheinfo`
  → `write-tree --missing-ok` → `commit-tree` → push. Verified the tree diff was **exactly 28
  additions, 0 deletions, nothing outside `images/`**, and that none of the 28 paths existed among the
  branch's 7,412 files. **Worth teaching that script the plumbing path so web sessions can use it.**
- **Short links must be resolved before hashing.** All 19 TikToks arrived as `vm.tiktok.com` and the
  YouTube links carried `?is=`. The id is uuid5 over `sourceURL`, so storing either form means the same
  post shared twice lands as two pins. `canonical_url` handles it (#590) — do not bypass it.
- **Two of four YouTube links hit Google's `/sorry/` interstitial** on first resolve from this
  datacenter IP. Transient; both resolved on retry. **Pace the resolver above ~50 links.**
- **A `SystemExit` from `make_one` is not caught by `except Exception`.** The tool's own batch loop
  gets this right; an ad-hoc resolver written during the session did not, and one bad link killed the
  whole run.

## Verification

`swift scripts/validate-tours.swift` via CI (**Validate Tours.json green**) — the authoritative check,
since a Linux web session has no Swift toolchain. Locally, a Python mirror **self-tested against 9
injected fault classes (9/9 caught)** before being trusted: link pin inside `tours`, non-link inside
`linkPins`, unknown tag, duplicate tour id, orphan `makerId`, bad category, link stop carrying audio,
coordinate out of range, malformed hero URL. Result: **0 errors, 0 warnings across 1512 tours + 18
link pins.** 0 id collisions for tours, stops and makers. All 28 images hash-verified against the
uploaded blobs **after** the Pages deploy (they 404'd for ~8 minutes first — the push succeeding is
not evidence the CDN serves it). Full CI green: validator, iOS Simulator build, unit tests.
