## The Plus Code decoder

`pip install openlocationcode` still cannot build a wheel here (fifth session running). Written
by hand and **self-tested to 24 checks before use**:

- the pair place values **derived from the specification** (160000, 8000, 400, 20, 1 in units of
  1/8000°) with `PLACE[0] == 20**4` asserted — the value session 130's bug got wrong;
- the published anchors: Eiffel `8FW4V75V+8Q` → 48.8583125, 2.2944375; `7FG49Q00+` → SW corner
  20.35, 2.75 with a 0.05° cell; `7FG49QCJ+2V`;
- **floor, never round** — `encode(20.375, 2.775, 10)` must be `7FG49QGG+22`;
- ⚠️ **the documented `+32` trap**: the `3` lands in the **latitude** slot and `2` (index 0) in
  longitude. Both orders plus the both-digits case are pinned;
- **Hong Kong's own area code `7PJP` is derived, not recalled** (and Manhattan's `87G8` beside
  it as a control);
- a short code is the full one minus its first four characters;
- **2,000 round-trips**, `recover_nearest` across four hemispheres, and **grid digits (>10)
  refused rather than guessed**.

⚠️ `decode` had to be patched once during the self-test: `0` in a code is **padding**
("not specified"), not a digit, so `7FG49Q00+` must have it stripped before the pair walk.
