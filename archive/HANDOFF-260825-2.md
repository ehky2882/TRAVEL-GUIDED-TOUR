## Four fields had the fatal shape, not one

`Tour.kind`, `Tour.primaryCategory` (10 cases), `Tour.videoRole` (optional) and
`Stop.triggerMode`. Any one of them meeting an unfamiliar value failed its tour,
which failed the whole `[Tour]` array, which `RemoteCatalogLoader`'s `try?`
turned into a silent "no new content".

### 🔴 Optional does not protect — verify this before you rely on the opposite

It is tempting to read `let videoRole: TourVideoRole?` and conclude a bad value
is survivable. It is not:

| payload | synthesised `decodeIfPresent` |
|---|---|
| key absent | `nil` |
| `"videoRole": null` | `nil` |
| `"videoRole": "brandNew"` | **delegates to the enum and PROPAGATES the throw** |

So an optional closed enum is exactly as fragile as a non-optional one, and
`videoRole` survives now **because of an explicit fallback, not because of the
`?`**. Pinned by `CatalogDecodeToleranceTests` with a **strict control enum**
declared in the test itself, so the point still holds even if every enum on the
model later gains a fallback. A second test asserts an unfamiliar `videoRole`
comes back as `.gallery` and **not nil** — nil is what "the optional absorbed
it" would look like, and that is not what happens.

## Layer 1 — per-field tolerance

Implemented as a custom `init(from:)` on each enum, which is a two-line change
per enum and leaves `Tour`/`Stop` on their synthesised decoders. Writing a
custom `init(from:)` for `Tour` would have meant hand-listing ~25 fields, where
a field added later is silently not decoded.

| field | default | why that one |
|---|---|---|
| `Stop.triggerMode` | `.manual` | **Load-bearing.** `ProximityMonitor` registers regions only for `.geofenced` stops, so a rule we did not understand can never produce a geofence that fires by itself. The failure is "press play" — visible and harmless. `.geofenced` would invent a region from a rule nobody read. |
| `Tour.videoRole` | `.gallery` | B-roll. The worst a misunderstood clip can do is sit in the carousel and play on its own; it never takes over the transport. `.narration` would let it seize the play bar. |
| `Tour.primaryCategory` | `.culturalHeritage` | The widest existing bucket (its icon is a globe), so it claims nothing the tour has not said — `.hiddenGems` would. The tour is still a good tour; only its shelf is uncertain. Browse has been keyed on `tags` since Tag Phase 2 anyway. |
| `Tour.kind` | **none — still throws** | See below. |

### 🔴 `kind` deliberately does not fall back

Owner's reasoning, not a style choice, and there is a comment on the enum saying
so: **rendering an unfamiliar pin as an ordinary tour is worse than not showing
it.** A link pin decoded as `.single` appears with a play button and no audio
behind it. A control that lies is worse than a pin that is absent.

An unknown `kind` therefore **drops that one tour** via layer 2.

⚠️ If a future session arrives to "tidy up" the inconsistency by giving
`TourKind` an `init(from:)` like its three neighbours — that is the change the
comment exists to stop.

## Layer 2 — the tolerant array, and this is the real protection

Every array in `ToursData` (`makers`, `tours`, `linkPins`, `places`) decodes
**element by element**. One unreadable element costs that element, not the
catalogue.

This is what covers every field nobody thought to guard, including ones added
years from now — layer 1 only covers the four closed enums we can currently
name. It is also what makes `kind`'s strictness affordable.

### ⚠️ The obvious implementation is a trap

Looping an `UnkeyedDecodingContainer` and `try?`-ing each `decode` is **not**
safe: whether `currentIndex` advances past an element that threw is not
guaranteed, so it can spin forever. Instead each element is wrapped in a type
whose `init(from:)` **cannot throw**:

```swift
private struct Tolerated<Wrapped: Decodable>: Decodable {
    let value: Wrapped?
    init(from decoder: Decoder) throws { value = try? Wrapped(from: decoder) }
}
```

The array decode then always succeeds and each element is attempted
independently. No index arithmetic, nothing to get wrong.

### ⚠️ Tolerance is for ELEMENTS, not for the document

A payload with no `tours` key, or no `makers` key, still throws — pinned by a
test. That is how the loader says *"this source is unusable, try the next one"*,
and it is the mechanism that makes the Supabase → gh-pages → cache → bundle
fallback chain work at all.

## ⚠️ A dropped element is counted, never swallowed

The brief was explicit: do not make the loader quieter than it already is.

- **`CatalogDecodeLosses`** carries per-array counts and rides on the decoded
  `ToursData` (not part of the wire format — it describes the decode).
- The **three** decode sites (network, cache, bundle) now go through one
  `decodeCatalog(_:from:)` helper in `RemoteCatalogLoader`, which logs a
  non-zero total via `os.Logger` with the source named and `privacy: .public`
  throughout — a redacted `<private>` in Console is as useless as no log.
- The outright-failure path is still `try?`. That is not silence; it is the
  loader's fall-through signal.

## Two tests encoded the old contract and were changed deliberately

Not deleted quietly. Both carry a comment naming the old contract and why it
changed:

- `ToursDataDecodingTests.test_decodingStop_badTriggerMode_throws`
  → `test_decodingStop_unknownTriggerMode_fallsBackToManual`
- `TourCategoryTests.test_decodingBadValue_throws`
  → `test_decodingUnknownValue_fallsBackToNeutralCategory`

**`test_decodingTour_badKind_throws` is unchanged and still passes** — it gained
a comment explaining that `kind` is the deliberate exception. That is the test
the brief named, and it did not need to move.
