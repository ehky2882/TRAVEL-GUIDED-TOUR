## What started it

Owner, with a screenshot of the Library list: *"These tour heroes are duplicated.
Thyssen borne is incorrect."* Museo Thyssen-Bornemisza and Museo Reina Sofía were
showing the same photo.

`museo-thyssen-bornemisza_hero.webp` was **byte-identical** to
`museo-reina-sofia_hero.webp` (sha256 `4aba0696…`). A wrong building on a live
tour since 25 June.

## Root cause — provable from git, worth reading

Two `gh-pages` commits, **40 seconds apart**:

```
21:10:17  41a03d5  Stage Madrid Reina Sofia images (owner-supplied hero + glass-capsule gallery)
21:10:57  103c90c  Stage Madrid Thyssen images  (owner-supplied hero + salmon gallery interior)
```

Both hero blobs share the **identical git hash** `6c6c7563…`. The Thyssen commit
re-used the image decoded 40 seconds earlier. Two owner-pasted images staged
back-to-back; the second paste was never written.

Everything *else* in that commit was correct — the `_2` salmon gallery interior is
the real Thyssen hall, and `IMAGE-CREDITS-madrid.txt` correctly omits a line for
the hero (owner-supplied images need no credit). **The intent was right; only the
bytes were wrong.** That is exactly why review missed it.

### ⚠️ The original was unrecoverable — and why

The owner remembered supplying a Thyssen hero. They had. It is **not in the repo
anywhere**: only one commit ever touched that path, and no branch, draft, or
historical commit holds another copy. Inline-pasted images live as base64 in the
session transcript at `/root/.claude/projects/<id>.jsonl` — but **a web session's
container is fresh-cloned, so prior sessions' transcripts do not exist locally.**

The owner re-pasted, and that paste *was* recovered from **this** session's
transcript (18 images in the `.jsonl`; the last was theirs, 1448×1086 — exactly
4:3, so it resized to 1200×900 with no crop).

**Durable rule: when an owner-pasted image is the only copy, hash the written file
against the decode before committing.** A lost paste cannot be re-fetched.

## The fix

No `Tours.json` change was needed — the URL was always correct, only the bytes
were wrong. Replacing the single `gh-pages` file also fixed **gallery slide 4 of
the Paseo del Arte walk**, which reuses that file and was therefore showing Reina
Sofía twice in one carousel.

Also this session: **Madrid de los Austrias got its own hero** (owner-picked CC0,
Philip III + Casa de la Panadería, 1200×900 q78). It had been reusing
`circulo-de-bellas-artes_hero.webp` — a Gran Vía rooftop view, geographically
wrong for a walk through the Habsburg quarter (Sol → Plaza Mayor → San Miguel →
Plaza de la Villa → Palacio Real).

## `scripts/check-image-duplicates.py` — the new guard

**This bug class is invisible to `validate-tours.swift`.** The URLs are distinct
and every one returns HTTP 200. Only the bytes match. Catching it means hashing
the actual files, which is why it is a separate script and not a validator rule.

Downloads every referenced image, groups by SHA-256, classifies each group:

| verdict | meaning |
|---|---|
| **ERROR** | two gallery slides of one tour are identical — a dead swipe |
| **ERROR** | two different tours share an image — a mis-stage, *or* one photo that genuinely shows two adjacent landmarks |
| **INFO** | a walk reusing a single-stop image, or a hero also in its own gallery — documented conventions, never fail |

The second ERROR is **a flag for human eyes, not an assertion of wrongness**. One
photograph can legitimately depict two tours' subjects (Millennium Bridge and
St Paul's). No script can tell that from the Thyssen bug.

**Not wired into `ci.yml`** — network-bound; a full run pulls 3,615 images. Run
`--maker <CODE>` when staging a city, which is when this bug appears. `--selftest`
pins the rules with no network. Cache under `.cache/` (gitignored).

### ⚠️ Read a full run before trusting your own rules

The first revision flagged **18** groups, **4 of them legitimate**:

- a walk hero picked from one of its own stop images (deliberate, not a mistake)
- a compound `_stopN_hero` filename the slug parser mis-read

A second refinement came from **Ponte Sant'Angelo**, whose photo legitimately
serves both the Vatican & Borgo walk stop *and* the Castel Sant'Angelo gallery.
The gap was real: an image used as a walk's **stop** image does not resolve to the
parent walk's slug, so it fell through to the single-vs-single rule. Fixed in the
tool, not whitelisted in content — and kept **deliberately narrow**: a walk's
**gallery** sharing bytes with a single-stop hero is exactly the Thyssen bug and
must still error. Selftest asserts both directions (8 cases).

**A rejected design worth recording:** a URL-level duplicate check in
`validate-tours.swift` was planned and dropped. It would not have caught either
Madrid bug. A check that looks like coverage but isn't is worse than none.

The check's fetch step turned up two **404s** unrelated to duplicates:

## Tribal knowledge earned this session

- **⚠️ `git push … | tail -3` inside an `if` reads *tail's* exit code, not git's.**
  A rejected non-fast-forward push reported "PUSH OK". Check `${PIPESTATUS[0]}`.
  Caught only because the live-URL hash still showed the old file.
- **⚠️ gh-pages Pages deploys were flaky.** One push's deploy came back
  **`cancelled`** and the CDN served the stale file ~10 min; a later unrelated
  push carried it through. Same race as the historical `f1242b1 Re-trigger Pages
  build`. **Verify by hashing the live URL, never by the push succeeding.**
- **`Tours.json` round-trips losslessly** as
  `json.dumps(d, indent=2, ensure_ascii=False)` with **no trailing newline** —
  verified byte-identical. So catalog edits can be done in Python with a minimal
  diff instead of fragile text surgery.
- **⚠️ CC0 coverage of famous landmarks is thin and skews historical.** Openverse,
  the Commons categories, a broad Commons search *and* a geo-search around the
  museum all failed to produce a head-on Villahermosa facade — that view exists
  only under CC BY-SA. **Owner-supplied photos remain the practical source for the
  classic view of a major landmark.**
- **`pull_request_read get_status` returns `total_count: 0` even when CI is green** —
  those are check *runs*, not commit statuses. Use `actions_list list_workflow_jobs`.
