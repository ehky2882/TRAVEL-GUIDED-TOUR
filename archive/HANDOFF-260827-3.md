## 🔴 BOTH YOUTUBE LINKS "FAILED" AND BOTH ARE ALIVE

`youtu.be/SUAhsSRUuf8` and `youtu.be/ZFecSI_Q0Ss` both resolved to
**`google.com/sorry/index?continue=…`** — Google's interstitial for datacenter
IPs — so `derivable_embed` returned `None` and the tool called them unpinnable.
This is documented (session 112) and it will recur.

**The bypass is deterministic, not a guess.** `youtu.be/ID` canonicalises to
`youtube.com/watch?v=ID` and nothing else; that URL satisfies
`is_already_canonical`, so `canonical_url` **skips the redirect hop entirely**
and the `/sorry/` page is never fetched. Both then returned full oEmbed.

⚠️ **Do not "fix" this by adding youtu.be to `CANONICAL_HOSTS`.** The tool
excludes it deliberately: the tour id is uuid5 over `sourceURL`, so the same
video shared both ways would hash to two pins. Constructing the watch URL
*before* handing it to the tool preserves the single canonical spelling.
