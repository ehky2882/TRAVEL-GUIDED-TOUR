## 🔴 IT WAS NOT ONLY THE GALLERY. THE LONDON TOUR HAS BEEN PLAYING THE LOS ANGELES NARRATION.

The London **Natural History Museum** and the **Natural History Museum of LA County** both used the
bare slug `natural-history-museum`, so both pointed at the **identical `audioURL`** —
`audio/natural-history-museum.mp3`. One file can live at one path.

**The live file measures 129.7 s.** The LA tour declares 130 s; London declares 160 s. So the file
serving both tours is the **LA narration**, and the London tour has been playing it since the LA
batch overwrote it on **2026-07-15** — six and a half weeks. Stand outside the museum in South
Kensington, press play, hear about Los Angeles. **No error, no missing asset, nothing any check
would flag.**

**⚠️ The reported symptom was the smaller half of the bug.** The gallery mix-up is what was visible;
the audio is what mattered. **When two entries share an image URL, check whether they share an audio
URL too** — the same bare slug produces both.

**A THIRD TOUR WAS AFFECTED and was not in the original report: the `Albertopolis` walk** uses

reference to the eight URLs rather than assuming only the two named tours were involved.**

## The fix

**Everything was recoverable from gh-pages history** — the pre-overwrite blobs are still in the
object store. All eight London assets were extracted **byte-identically** (the staged blob SHAs are
literally London's original ones) and republished under **`natural-history-museum-london`**.

**🔴 A NEW ADDRESS, NEVER AN OVERWRITE.** Per #567, a phone that has downloaded a tour reads its
audio and photographs off its own disk and never asks the server again, so a correction made in
place would reach nobody who already has the tour. A new filename is a new address, so every phone
fetches it automatically.

| Entry | Change |

| **Natural History Museum** (London) | audio + hero + `stops[0].imageURL` + all 6 gallery → `-london` |
| **Albertopolis** (London walk) | gallery entry + `stops[2].imageURL` → `-london_hero` |
| **Natural History Museum** (place) | hero `_5` → `-london_5` |
| **Natural History Museum of LA County** | gallery **6 → 3**, dropping `_5.._7` (London images) |

**⚠️ The LA tour deliberately keeps the bare slug** for its hero, `_2`–`_4` and its audio: those URLs
now serve LA content, and the LA tour is the one they are correct for. Moving it too would mean
repointing a tour that is currently right. The bare slug is now owned by exactly one tour, which is
the normal state for everything else in the catalogue.

## 🔴 Owed — this is a CLASS of bug, not an instance

The bare-slug collision is what the handle/city suffix convention exists to prevent, and here it hit
**audio as well as images**. **Nothing in the pipeline checks for two catalogue entries sharing an
`audioURL`.** `check-image-duplicates.py` compares image *bytes*, which cannot see this: the two
tours pointed at one URL, so there was only ever one file to hash.

**A whole-catalogue sweep for shared `audioURL` and shared image URLs across different tours has NOT
been run.** It is cheap and it is the only thing that would find another instance. Recommended next.
