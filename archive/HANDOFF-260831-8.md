## 🔴 The Plus Code decoder failed its own self-test, and the bug was real

`pip install openlocationcode` still cannot build a wheel here, so the decoder was
hand-written again. **Its first run FAILED** — every decode came out about 105
degrees wrong — because the pair section's **first place value is 20⁴ (= 20 degrees
in units of 1/PAIRPREC), not PAIRPREC itself**. One line.

CLAUDE.md warns twice that the *memory* of a test vector is the usual culprit and the
arithmetic is usually right. **This time the arithmetic was wrong and the test caught
it**, which is only possible because every expectation is derived from the
specification's own pair table (20, 1, .05, .0025, .000125) rather than recalled.
Keep it that way.

The self-test that now passes:

- **8 codes** checked against SW corner + cell size derived by hand from the pair
  table — including all four full codes this batch carried.
- **3 published anchors**: `7FG49QCJ+2V` → 20.3700625, 2.7821875 · `7FG49Q00+` →
  20.375, 2.775 · `8FW4V75V+8Q` → 48.8583125, 2.2944375 (the Eiffel Tower value
  CLAUDE.md records from session 122).
- **The documented integer-encode bug**: `encode(20.375, 2.775, 10)` must be
  `7FG49QGG+22`. A float encode computes `0.375/0.05` as 7.4999… and emits
  `7FG49QFG+X2`.
- **2,000 random round-trips**, both directions.
- **`recover_nearest` across four hemispheres**, plus the specific case this batch
  needs: NYC straddles the **−74° pair boundary**, so Manhattan is `87G8…` while a
  reference point at −74.006 is `87G7…`. Three of this batch's codes recover to
  `87G7` (Battery Park City, the 56 Leonard bean, the Greenwich Street bookshop) and
  the rest to `87G8`. A decoder that got that wrong would put pins in the Hudson.

Reference for the short codes: `New York, USA` geocoded to 40.71273, −74.00602.

## ⚠️ Process notes worth keeping

- **`echo "EXIT=$?"` after a pipe reads the LAST command's status, not the script's.**
  Running `check-place-candidates.py | tail` and echoing `$?` reported **EXIT=0** when
  the script had actually exited **1**. That is the documented `PIPESTATUS` trap from
  session 90, and it nearly went into this handoff as a pass. Redirect to a file and
  read `$?`, or use `${PIPESTATUS[0]}`.
- **A transient TikTok CDN SSL failure killed the first generation run outright**
  (`SSL_ERROR_SYSCALL` to `p16-common-sign.tiktokcdn-us.com`) and, because the driver
  had no retry, took the whole run's state with it. The rewritten driver **checkpoints
  after every pin and retries four times with backoff**, so a 50-row batch survives
  one bad packet. Worth folding into any future batch driver.
- **No `5009` CDN refusals this batch** — the failure class that hit 13 of 95
  thumbnails in #674 did not recur, and all 50 oEmbed payloads carried a caption, an
  author and a thumbnail.
