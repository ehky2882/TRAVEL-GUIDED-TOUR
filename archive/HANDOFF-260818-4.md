## 🔴 The durable rule: a presenter must dismiss its own layer

`TourPresenter.dismiss()` set `presentedTour = nil` and stopped there.
The UIKit layer came down only because `ContentView` observed that
property and called `bottomLayer.dismiss()`.

`ContentView` lives in the **main window**, which a slide-up layer
covers completely, and SwiftUI can stop delivering updates to a
hierarchy hidden behind a modal presentation. So on the path

    tour → maker → close maker → tap a tab

the write landed, the observer never ran, and the layer stayed on screen
with the tab bar apparently dead.

Every presenter now carries

```swift
@ObservationIgnored var performDismiss: (() -> Void)?
func dismiss() { presentedX = nil; performDismiss?() }
```

wired once in `ContentView`'s `.onAppear`. The layer collapses itself;
nothing depends on a window still being live.

**This is the third instance of the same class in this codebase** — the
session-93 tab-bar bug and the batch-D Follow button were both a side
effect parked somewhere a modal could cover. Treat "put the side effect
in the window that can never be covered" as the rule, not the fix.

## 🔴 Two wrong theories, both reasoned from code, both settled by a screenshot

**#528 — "a clustered place pin is unreachable."** False. A place sits at
a coordinate distinct from its neighbours (it *replaces* its own tours,
so what surrounds it is other tours elsewhere), which means zoom
separates it normally. The exemption shipped and the pin was still dead,
because the cause was the dismissal bug above.

Worse, the exemption made the map lie. At world zoom a lone `2` capsule
floated beside a `100` cluster, reading as though a whole region held two
tours. The owner caught that from a screenshot; no check we run can see
it.

Reverted in #536, which also changed the badge to count tours:

```swift
let tourCount = stops.reduce(0) { $0 + ($1.isPlace ? $1.placeTourCount : 1) }
```

so a cluster holding a 2-tour place plus two singles reads **4**, not 3.

**The pattern worth naming:** each failed round was me reasoning from the
code about what *should* break, rather than getting evidence about what
*was* breaking. Each owner screenshot resolved in one image what a build
of guessing had not. Ask for the screenshot first.

## ⚠️ Clustering tests: compute the bucket, don't eyeball the decimals

#536's first CI run failed on its own new test. Buckets key off an
**absolute (lat 0, lon 0)** grid, so at a 0.1° span with 12 cells across
the pitch is 0.008333° and a row boundary falls on **latitude 45.5
exactly**. A marker written at 45.5001 bucketed one row up, so the
cluster held the place plus one marker and counted 3 where the test
demanded 4. The assertion and the production code were both correct.

Round numbers are exactly where the boundaries are. Compute
`floor(lat / cellSpan)` for your test coordinates before trusting them.
