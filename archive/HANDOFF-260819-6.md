## 🔴 Two bugs that were NOT in the ask, and one of them had shipped for months

- **`Version 1.0` was a hardcoded string** while the app target has been on
  `MARKETING_VERSION = 1.1` since build 46. Every tester has been reading the
  wrong version off that screen. `Info.plist` already fills
  `CFBundleShortVersionString` / `CFBundleVersion` from the build settings, so
  the values were sitting in the bundle unread. The build number is included
  deliberately — a marketing version cannot identify a TestFlight build, and
  *"which build are you on?"* is the first question on every report.

- **🔴 THE WORDMARK WAS NEVER GOLD, AND THE CALL SITE LOOKED CORRECT.** It read
  `.foregroundStyle(AtlasColors.mapPin)` and drew white. **`accent` and `mapPin`
  are both `Color.accentColor`, which resolves the ENVIRONMENT's accent** — and
  `SettingsView` pins `.tint(AtlasColors.primaryText)` on its List on purpose,
  to stop the system auto-tinting every row icon and button label gold. That
  tint repaints anything on the screen reading the accent, the wordmark
  included. Nothing in the file pointed at the cause; the two lines are 200
  apart.
  - **Fix: `AtlasColors.brass`** — the same `#8B7535` as a **literal**, immune to
    `.tint`. Same reasoning as `secondaryBackgroundUIColor`, which is already a
    hardcoded pair in that file because a semantic colour resolved differently
    by context. **The `.tint` line now carries a note about what it repaints**,
    so the trade-off is visible from both ends.
  - **⚠️ Anything that must stay brand-coloured on a surface that sets its own
    tint has to use `brass`, not `accent`/`mapPin`.** `mapPin` has ~58 call
    sites; they are fine because those surfaces don't re-tint.
  - **The owner caught this on a device.** It was visible in their very first
    screenshot — a white wordmark — and was described as brass throughout the
    PR, the build notes and the mockup, which drew it gold. **A screenshot is
    evidence; check the pixels against the code rather than narrating the
    code.**

## Country: why it went in the DATA and not in Swift

Owner's stated principle, from the version fix: *"should automatically update."*

**There was no country anywhere** — not on `Tour`, not on `Maker`, not in
Postgres. Two options were measured and the owner took the first:

- **Catalog data** (chosen). Travels with content, so it updates over the air
  on a content merge. Costs one SQL paste.
- **A city→country table in Swift** (rejected). No SQL — but **a city launch
  merges as content and reaches phones with NO build**, so a table compiled into
  the binary starts understating the day a city lands. That hole sits exactly
  where this project ships most often.

**How the mapping was made safe:** all 103 cities mapped **explicitly**, then
every tour cross-checked against the **bureau that authored it** (`Atlas Studio
BCN` → Spain, and so on). A mistyped country fails the pass rather than being
silently inherited. Bureau data was used only to *check* the table, never to
build it. Result: 1,418 tours, 20 countries.

- **`Tour.country` is optional and that is load-bearing** — the bundled seed and
  the gh-pages mirror predate the key until republished, and maker-authored
  tours (`MakerTourService`) have no country at all. Both call sites there pass
  `nil` deliberately, with a comment.
- **`backend/add_country.sql` lifts its `get_catalog` body VERBATIM from
  `schema.sql`** (the script reads the file and slices between the function
  header and `$$;`), so the migration and the canonical schema cannot drift.
- **The Countries row hides at zero rather than printing "0".** Between the app
  shipping and the column being filled, "we don't know yet" is a missing row,
  not a count of none. It appeared on its own after the merge — **no rebuild**.

## Process notes

- **`.tint` is the third instance of a screen-wide setting silently repainting
  something specific** — after `UISegmentedControl.appearance()` (session 77b)
  and the `.preferredColorScheme` that never reached the secondary window
  (session 12). **When a call site says one colour and the screen shows another,
  look for an ancestor modifier before doubting the call site.**
- **The shell cannot reach `api.github.com`** (403 — GitHub access is not
  enabled for the session); only the MCP tools can. A polling loop written with
  `curl` exits silently and tells you nothing. Poll through the tools.
- **`actions_list` on a busy workflow returns ~420 KB** and blows the tool
  budget. Use `list_workflow_jobs` on a known run id instead.
- Build notes were attached to both builds via the `notes` workflow input, and
  **build 86's notes explained in plain language why the Countries row was
  absent** — so a deliberate empty state could not read as a bug on the phone.
- Two TestFlight builds this session, **5 and 7 minutes** end to end. No
  certificate-cap fast-fail.
