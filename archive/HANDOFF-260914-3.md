## 🔴 Two mistakes caught before they shipped — worth knowing for the next batch

1. **`make-link-pin.py --batch` output is `{"linkPins": [...], "makers": [...]}`, not a
   flat list.** A first pass did `all_pins.extend(payload)` across 25 group calls, which on
   a dict iterates its *keys* ("makers", "linkPins") as strings. Caught by inspecting the
   combined file before merging — nothing bad reached `Tours.json`. Fixed by extending
   `payload["linkPins"]` and de-duplicating `payload["makers"]` by id across groups.

2. **The tag-facet validator caught 28 warnings the first `merge-link-pins.py` run didn't
   surface as errors.** `validate-tours-mirror.py` wants every pin to carry ≥1 tag from
   the **Place type** facet and ≥1 from **Theme** (`TRAVEL GUIDED TOUR/Models/Tag.swift`).
   My tags leaned on theme/experience (Food, Commerce, Hidden Gem, After Dark…) and missed
   placeType on 26 pins, and missed theme on Grandfather's / Todoroki Valley ×2 / Yakushu
   Bar. Patched 27 pins with an extra tag each (mostly `Venue` or `Notable Building` for
   placeType; `Performance`/`History`/`Commerce` where theme was missing) directly on the
   merged JSON. Re-ran the validator: 0 errors, 0 warnings from this batch (5 pre-existing,
   unrelated warnings remain — UIC Skyspace, Gerry's Pompeii, etc.).

## Merge conflict with a parallel session

Between opening PR #885 and merging it, **PR #886** ("Add 34 link pins from a mixed
creator batch") — a different session's work — landed on `main` first. Both PRs appended
new entries near the same spots in `Tours.json`'s `linkPins`/`makers` arrays, producing a
dense, many-hunk git conflict.

**Did not resolve it by hand-editing conflict markers in an 11 MB generated file.**
Instead: `git merge --abort`, checked out the fresh `origin/main` copy of `Tours.json`,
re-ran `merge-link-pins.py` (idempotent, JSON-aware) with my already-approved 38-pin
payload on top of that fresh base, reapplied the same 27 tag-facet fixes, validated again
(clean), then completed the merge commit. CI re-ran clean on the merge commit. This is the
safer pattern for this kind of conflict — regenerate through the tool, don't text-merge
generated JSON.
