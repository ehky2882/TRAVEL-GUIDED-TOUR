## What was actually wrong

Two independent defects on one screen.

**1. The gate was "owner only".** `backend/social.sql` guarded both
`list_followers` and `list_following` with

```sql
if exists (select 1 from public.makers mk where mk.id = m and mk.is_private)
   and not public.owns_maker(m) then
    return;
end if;
```

so a private account's graph was withheld from **everyone except its own
owner** — accepted followers included. That is not the owner's model; it has
been written down since 2026-07-27: *"if a maker is public then everything is
public. if maker is private but you are friends then you should be able to see
your friend's list."*

**2. The empty state lied.** The count above it said **1** — the owner
themselves — while the list said "No followers yet." The RPC returns the same
empty array whether the list is withheld or genuinely empty, and
`FollowListView` always assumed the second.

## Still open — found while reading, deliberately not touched

1. **A private account's tours are visible to everyone**, signed-out included.
   `get_catalog` is one public payload with no viewer and `is_private` never
   filters it. The creator in the screenshots has his one tour served to the
   whole app. This is the standing "private should hide everything" project and
   it collides with the offline/anonymous catalog design — see CLAUDE.md for
   the three options and why the hybrid is the likely answer.
2. **Lists ignore the friendship entirely.** `journeys_read` is
   `owner_user_id = auth.uid() or is_public` — the maker's private flag plays
   no part, so Shared reaches strangers and *Only me* is hidden from friends.
   The owner's stated model has no code behind it. `can_see_social` is the
   door this will want.
3. **`liked_tour_ids(p_user)` has no visibility check at all** and is granted
   to `anon`. Anyone can read anyone's Liked.
4. **The counts are not gated** — `follow_state` returns `followers` /
   `following` to anyone, which is why a private account shows
   **1 followers · 116 following**. Publishing the totals while hiding the
   names is inherited from `social.sql`, not introduced here; if the owner
   wants the counts hidden too that is a third place to change.
