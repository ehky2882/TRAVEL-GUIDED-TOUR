## The Plus Code decoder

`pip install openlocationcode` still cannot build a wheel here (fourth session running),
so it is hand-written again. **Every expectation is derived from the specification's own
pair table, never recalled** — CLAUDE.md warns twice that the memory of a vector is the
usual culprit.

The place values, derived rather than remembered: `20, 1, 1/20, 1/400, 1/8000` degrees,
which in integer units of 1/8000° are `160000, 8000, 400, 20, 1` — and **160000 is 20⁴,
the value session 130's bug got wrong.**

Passing suite, **19/19**:
- **Published anchors** — Eiffel `8FW4V75V+8Q` → 48.8583125, 2.2944375; `7FG49Q00+` →
  20.375, 2.775; `7FG49QCJ+2V` → 20.3700625, 2.7821875, each re-derived by hand first.
- **Six full codes decoded independently** by a second implementation written straight
  off the pair table, agreeing with the decoder's loop.
- **`encode` must FLOOR, not round** — `encode(20.375, 2.775, 10)` must be
  `7FG49QGG+22`; exact `Fraction` arithmetic throughout.
- **🔴 The −74° pair boundary.** Manhattan encodes `87G8`, a point at −74.006 encodes
  `87G7`. Three of this batch's codes correctly recover across it — **#14 (33 Thomas
  Street, Tribeca) and #16 (Chelsea)** both land west of −74. A decoder that got this
  wrong would put those pins in the Hudson.
- **A short code is the full one minus its first four characters** — asserted directly.
- **2,000 random round-trips** and **500 `recover_nearest`** round-trips, four
  hemispheres.
- **Grid digits (>10 characters) RAISE rather than guess.** Whether the grid's row 0 is
  the north or south edge cannot be settled from any vector verifiable here, and no code
  in this batch uses one.
