**Nothing downstream would have caught it.** `validate-tours-mirror.py` passes, CI compiles, every

Two days, two batches, two coordinate faults from the same upstream. Both invisible to every
automated check. **The read-back is now the load-bearing step of a pin batch, not a courtesy.**

All 28 supplied coordinates were read back the same way, by reverse-geocoding the recovered point
and comparing the name that came back against the caption's subject. Every other one agrees, most

## ⚠️ Nominatim 429s on a shared proxy — Photon is the fallback

`nominatim.openstreetmap.org` started returning **HTTP 429** partway through the read-back and
then refused everything, including single requests spaced three seconds apart. The web-session
proxy shares an IP, so the polite 1 req/s limit is not ours alone to spend.

**`https://photon.komoot.io` answered every one of them** — same OSM data, both `/reverse?lat=&lon=`
and `/api?q=`, no key, and it is what resolved Foley Square, the Roman Ghetto, Edinburgh Castle and
all ten of the unlocated pins. Worth reaching for first on a large batch, or keeping in reserve.

Two subjects it would not find by name and that needed a second query: **Bethesda Terrace**
(returned "Terrace at Nougatine"; confirmed instead by reverse-geocoding the known point) and
**Villa Charlotte Brontë** (no result by name; found by its address, 2501 Palisade Avenue).

## Titles are the subject, not the caption

`make-link-pin.py --batch` ignores `--title` and `--slug` (single-`--url` runs only), so a batch run
would have put *"👀 Is this fact or fiction? #mexicotiktok #christiantiktok"* on the map. Each pin
was minted individually with an explicit title **and slug** — 38 runs, output redirected per pin so
no pin JSON entered the conversation.

The explicit `--slug` is worth the extra column: derived slugs turn an apostrophe into `-s-`, so
the first trial run produced `olana-frederic-church-s-hilltop-house-urbanistariel_hero.webp`.

No title collides with anything live, checked against all 1,552 tours and 1,551 pins before minting.

## Two process notes from the merge

**`main` moved during CI and the merge conflicted — on `archive/README.md` alone.** #781 landed
another session's handoff and rewrote the `HANDOFF-260909-4.md` index row while #782 sat open with
green CI. Structural, so it was resolved in line: main's richer `-4` row kept, this session's `-5`
row added above it, `Tours.json` untouched by the merge and re-validated afterwards
(0 errors, 0 warnings). ⚠️ The `213 entries` line under that table counts `INDEX-DETAIL.md`
long-form entries, **not** table rows (221 of them on main) — a new handoff row does not move it.

**Two pushes produced no `synchronize` event, so CI never re-ran on the real head.** Both times the
PR page showed green from the *previous* commit. `ci.yml`'s own `workflow_dispatch` comment
documents exactly this gap for web sessions; it was dispatched by hand twice, and the second run
caught nothing but proved the head. **A green tick on a PR is not a green tick on its head commit —
read the run's `head_sha`.**

⚠️ **A `pkill -f` pattern matched the process that was issuing it.** Killing a Supabase poll with
`pkill -f "catalog_snapshot_age"` from a shell whose own command line contained that string killed
the replacement poll as well, twice over. Put the loop in a script file and run that instead.
