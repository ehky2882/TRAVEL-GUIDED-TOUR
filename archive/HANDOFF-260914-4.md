## Two mistakes caught before they shipped

1. **A hero-filename collision.** Two posts both opened `"Comment 'SUSHI' below and we'll DM
   you…"` — Sushi Gotoroppo and Sushi & Wine Omotesandoria. `make-link-pin.py`'s auto-derived
   slug (from the caption, when no `--slug` is given) came out identical for both, so the second
   `--batch` call silently overwrote the first's hero file on disk, and both catalog entries
   pointed at one image and one URL. Caught by hashing every hero file after the batch run (72
   pins, 71 unique hashes) — not by trusting the merge's own success. Regenerated both with an
   explicit `--slug`, then had to patch **two** fields per entry: `heroImageURL` at the top level
   AND `stops[0].imageURL`, a separate field carrying the same URL that's easy to miss (only
   `heroImageURL` is documented as "the" hero field). Re-verified: 72 pins, 72 unique files, 72
   unique filenames referenced in the diff.
2. **Would have double-pinned into a same-day batch.** Started this session behind `main` by six
   commits, one of which (#885, this same afternoon) was *also* a Tokyo/Kyoto link-pin batch from
   a parallel session — different creators (`revisit_japan`, `tokyo24h.journey`, etc.), no direct
   overlap, but re-synced to `main` and re-ran the LIVE-pin check plus a venue-name grep against
   the just-merged catalog before minting anything, rather than trusting a triage done before the
   fast-forward. Came back clean.
