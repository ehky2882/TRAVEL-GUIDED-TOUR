## 🔴 A stale scratch file nearly reported a false pass, and only the count caught it

A command shaped `sed … && grep -n "<anchor>" file && python3 suite.py > out.txt; cat out.txt`
printed **"22/22 faults caught"**. The `grep` found nothing — the `sed` substitution had not matched,
because of quoting — so the `&&` chain **short-circuited and python never ran**. `cat` then printed a
**two-day-old file (Sep 5 02:53) left by session 145**.

It was caught **only** because 22 did not match this suite's 20.

**The fix, and the rule:** write a check's output to a **unique path** (`faults-run-$(date +%s).txt`)
and **confirm its write timestamp** before believing it; replace fragile `sed` value substitutions
with a Python edit on an **asserted-unique anchor** (`assert s.count(old) == 1`). A `&&`
short-circuit will otherwise hand you someone else's pass — the
`check-image-duplicates.py`-printed-OK class in a new place.

```
HTTP 200  1647ms · 1542ms · 1516ms · 942ms · 870ms · 1121ms  ← six clean samples after it
```

**The fault #742 fixes is still there**, because the SQL has not been applied — and it fired again
**after** the seed (`HTTP 500 / 57014` at 7.1 s) before the clean read above landed on the seventh

unfixed system behaving as documented, not a symptom of the content change. ⚠️ **Judge the fix by
the LATENCY BAND, not by a pass/fail count** — the session-146 lesson, where an 8/8 clean window at
the identical latency band meant nothing had improved. After the migration `get_catalog()` should be
a **sub-second lookup**; anything still measured in **seconds** means the snapshot is not being
served. The 0.87–1.65 s band above is the builder still running.

## ⚠️ `$SCRATCH` is not set in this container

Scripts written as `"$SCRATCH/foo.sh"` resolved to **`/foo.sh`** — I created `/await/`,
`/rpcsample/`, `/check_rpc.sh`, `/rpc.json`, `/rpc.meta`, `/wait_rpc.sh`, `/await_seed.sh` and
`/verify.json` at the **filesystem root** before noticing, and removed them all. **Use the
scratchpad path literally, or `echo "$SCRATCH"` first** — an unset variable in a path silently
writes to `/`.

⚠️ It also produced a **read/write race**: a foreground read of a file a background poll was
overwriting reported `HTTP 200 … 10649683 bytes` beside an error body far smaller than that. **Two
readers on one path give you a number from one moment and a body from another** — give a background
poll its own file, or read only what it prints.
