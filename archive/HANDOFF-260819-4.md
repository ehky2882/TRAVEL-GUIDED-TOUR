## What shipped

The tour upload became a **five-step wizard** — Location → Details → Photos → Audio → Review — from a design handoff the owner supplied, mocked up and agreed before any code was written.

**Deleted, not deprecated (~1,400 lines):** `CreateTourView.swift`, `TourAuthoringView.swift`, `TourDetailsEditorView.swift`, `PhotoManagerView.swift`, `Components/DismissAttemptGuard.swift`.
**New:** `CreateTourWizardView.swift`, `TourWizardRules.swift` (+ tests), `PhotoGridEditor.swift`, `PhotoFramingView.swift`, `AudioRecorderPanel.swift`, `TourAudioSection.swift`.

The wizard is now the **only** way a maker creates *or* edits — owner: *"i think the 'wizard' simply replaces the editor, no?"*, then *"i only want the wizard"*.

## 🔴 The bug worth carrying forward

**Opening a saved tour hung the app until the watchdog killed it (`0x8BADF00D`). Six builds, five wrong diagnoses — and the fix that shipped removes the sheet rather than the trigger: since build 89 the edit path presents via `.fullScreenCover`; create keeps its `.sheet`. Do not "restore consistency" by making edit a sheet again.**

### What every crash log agreed on

Three logs (builds 77, 84, 87), all watchdog `process-exit` with ~5–6 s of app CPU, all the same wedge:

```
UISheetPresentationController._transitionWillBegin:
  -> _sheetLayoutInfoLayout:
    -> layoutBelowIfNeeded
      -> _UIHostingView.layoutSubviews
        -> SwiftUI render
```

One **synchronous, never-returning layout call** — a frame chain only a *sheet* can produce. The top frames named a different function each time (`NavigationStack` body init in 77, `ToolbarBridge.updateLocations()` in 84, the Map's `PlatformViewChild` trait walk in 87) because **each crash log is a single sample of the same busy loop, caught at a different station. Never diagnose a spin from the top frame of one sample.**

### The falsification chain — do not re-walk it

- **Build 81:** `DismissAttemptGuard` (a representable setting `isModalInPresentation` from inside sheet layout) removed. Still hung.
- **Build 84:** camera writes gated on a coordinate tolerance; `interactiveDismissDisabled` fed from plain `Bool` state. Still hung.
- **Build 87:** toolbar made structurally constant (no `if` around `ToolbarItem`s); footer hint given reserved height. Still hung.
- **Build 88:** all of `loadExistingTour`'s state application deferred past the presentation transition and applied in one batch, fetches overlapped. **Still hung — and this falsified the whole model.** The wedge is one synchronous runloop callout; a `.task` cannot even begin executing while the main thread spins inside it, so our state writes were never the fuel. The loop is self-sustaining inside the sheet machinery, seeded by something in this screen's very first render — possibly an OS defect our layout provokes.
- **Build 89:** the sheet removed for the edit path (`.fullScreenCover`). Different presentation machinery; `_sheetLayoutInfoLayout:` cannot run.

### Why edit and never create

Unknown at the mechanism level — and the shipped fix does not depend on knowing. The suggestive history: **the old editor (`TourAuthoringView`) was pushed, never sheet-presented. Only the create form ever lived in a sheet, and the create form never hung.** Editing-in-a-sheet was the new combination this project introduced.

### Kept although they were not the fix — all correct on their own terms

- The coordinate-tolerance guard on `onMapCameraChange` (`CLLocationCoordinate2D` has no `Equatable`; an unchanged write still dirties the view). `isEssentially` in `TourWizardRules.swift`, pinned by tests.
- `.interactiveDismissDisabled` reading cheap, rarely-changing state — inert under `fullScreenCover`, load-bearing if the wizard is ever sheet-presented again.
- The toolbar and its `NavigationStack` deleted — the wizard never navigates; the stack existed only to host the toolbar. Plain header now.
- `loadExistingTour` fetches during the presentation and applies everything in **one batch after a 650 ms settle** — fields appear together, a beat after the screen lands, instead of in four waves.
- Programmatic field fills guarded on `focused`, so loading a saved tour can't fire the typed-in-it path (completer + dropdown).

### Process lessons, paid for in builds

- **When a fix fails, get the crash log for the build that failed.** Three builds were lost re-reading the build-77 log; its unsymbolicated `NavigationStack.init(root:)` frame was misread as the body under evaluation when it was the toolbar's host.
- `.ips` files: **Settings → Privacy & Security → Analytics & Improvements → Analytics Data**, newest file named after the app; trailing filename digits are `HHMMSS` local. A `.cpu_resource-*.ips` beside it is a **sampled profile** — better than a crash log for a spin.
- Build numbers are `github.run_number`, shared across every session — a build dispatched expecting 82 came back 84, another expecting 85 came back 87. **Read the number back after dispatching.**

## Owner decisions this session

- Photos capped at **7** ("seven photos so it's clean"); the cover is position one, and dragging to the front is how you promote it.
- Radius **15–100 m** (was 15–200; nothing in the catalogue has ever used past 40).
- **Nothing but a title is required.** Owner: *"It should be up to the creator. Simply makes their tour less discoverable?"* — this **corrected a gate I had invented**, and it matches `validate-tours.swift`, which treats a missing Place type or Theme as a **warning**, never an error. Short description optional too.
- **Framing and recording happen on their own steps**, not on separate pages — *"we should be able to accomplish everying in that 1 step"*.
- "published for review" → **"submitted for review"**. Save progress is a **button**, same weight as Next.

## Process notes

- A CI build log carried **exactly one `error:` line in 95,219 characters** — grep the whole log, never tail it.
- **`Self` is rejected in a stored-property initializer** even on a `final class` ("covariant 'Self' type cannot be referenced from a stored property initializer") — use the type's own name.
- The **job-status API lags**: a job reporting `in_progress` had already written `** TEST SUCCEEDED **` to its log.
- A CI unit-test job hung past 20 minutes with no downloadable logs; the documented **cancel-and-rerun** cleared it and the same job then finished in 3 minutes.
- **Build numbers are `github.run_number` and shared across every session** — this build was dispatched expecting 82 and came back **84**. Read the number back after dispatching; never promise it in advance.
