## 🔴 The bug worth carrying forward

**Opening a saved tour wedged the main thread until the watchdog killed the app (`0x8BADF00D`). It took three builds, and the first two diagnoses were wrong.**

The crash log named it in one frame: **`NavigationStack.init(root:)` inside `UISheetPresentationController._sheetLayoutInfoLayout:`** — the *root* body being re-evaluated from inside sheet layout.

The chain:

```
.interactiveDismissDisabled(… hasUnsavedChanges …)   // on the sheet's root
  → currentSignature
    → centerCoordinate                                // CLLocationCoordinate2D
```

`CLLocationCoordinate2D` **has no `Equatable`**, so SwiftUI cannot tell an unchanged write from a real one — **every** `onMapCameraChange(frequency: .continuous)` callback dirtied the root body. And because that value feeds `interactiveDismissDisabled`, each pass **reconfigured the presentation controller**, which laid the map out again, which fired the callback. 5 s of CPU, never converging.

**Why only an existing tour:** only `loadExistingTour` re-frames the camera *after* the sheet is already presented (it fetches the stop, then sets `cameraPosition`). Creating a tour never enters the loop — which is exactly why the first two guesses looked reasonable.

**Why it was hard to see:** the old `CreateTourView` wrote the coordinate **identically** for a year without hanging. It had **no `.interactiveDismissDisabled` at all** and an inert `Color.clear` safe-area inset, so nothing it wrote could reach sheet layout. **The write was never the bug; the root-level dependency was.** Diffing the deleted screen against the new one is what settled it — reading the new file alone had already failed twice.

### Three durable rules

1. **Whatever `.interactiveDismissDisabled` reads must be cheap and rarely-changing.** It reconfigures `UISheetPresentationController`, so it is a *layout input*, not a plain modifier. Pass plain `Bool` state, recomputed lower down where invalidation cannot reach sheet layout.
2. **Gate every coordinate write on a tolerance.** `CLLocationCoordinate2D.isEssentially` lives in `TourWizardRules.swift` with the reason beside it and two tests pinning it. Anywhere a coordinate `@State` is written from a callback that fires on layout, an unguarded write is a loop waiting for a second trigger.
3. **A computed property read in `body` is a root dependency even inside a `private var`.** `wizard`, `footer` and `mapSection` are all evaluated within `CreateTourWizardView.body`; splitting them into separate `View` types is what would actually scope their dependencies.

### Dead ends — already tried, do not repeat

- **`DismissAttemptGuard`** — a `UIViewControllerRepresentable` setting `isModalInPresentation` to *prompt* on the swipe. Same class of bug: mutating sheet state from inside sheet layout. File deleted.
- **Clamping the loaded radius** into 15–100. A real latent bug (tours predate the current slider) and worth keeping, but not this.
- **Two stacked `confirmationDialog`s** and **capturing a representable context across an async boundary** — both removed early, both ruled out by the owner's answer that only *existing* tours crash.

## Owner decisions this session

- Photos capped at **7** ("seven photos so it's clean"); the cover is position one, and dragging to the front is how you promote it.
- Radius **15–100 m** (was 15–200; nothing in the catalogue has ever used past 40).

Simply makes their tour less discoverable?"* — this **corrected a gate I had invented**, and it matches `validate-tours.swift`, which treats a missing Place type or Theme as a **warning**, never an error. - "published for review" → **"submitted for review"**. Save progress is a **button**, same weight as Next.

## Process notes

- A CI build log carried **exactly one `error:` line in 95,219 characters** — grep the whole log, never tail it.
- **`Self` is rejected in a stored-property initializer** even on a `final class` ("covariant 'Self' type cannot be referenced from a stored property initializer") — use the type's own name.
- The **job-status API lags**: a job reporting `in_progress` had already written `** TEST SUCCEEDED **` to its log.
- A CI unit-test job hung past 20 minutes with no downloadable logs; the documented **cancel-and-rerun** cleared it and the same job then finished in 3 minutes.
- **Build numbers are `github.run_number` and shared across every session** — this build was dispatched expecting 82 and came back **84**. Read the number back after dispatching; never promise it in advance.
