## The three findings worth carrying

**A project-path host can never serve an association file.** Apple fetches it
from `https://<host>/.well-known/apple-app-site-association` — the **domain
root**. The catalog is at `ehky2882.github.io/TRAVEL-GUIDED-TOUR/`, a project
path, so there was no root to put it at. Session 94 recorded this as a missing
file; it was a missing *host*. Now served from `dozent.world`, with
`site/vercel.json` forcing `Content-Type: application/json` — **Apple rejects
the file if it arrives as `text/plain`**, which is what Vercel guesses for an
extensionless file.

**A fixed hero height crops differently on every phone.** `heroHeight` was 320pt
everywhere while the width it sits in is not: 342pt on a 390pt screen, 272pt on
an SE. Same photograph, **8% cropped on one phone and 23% on another** — and
invisible in review because each device looks self-consistent. Replaced by a
ratio plus `.atlasHeroSizing(_:)`; the old constant is deleted so it can't
return.

**The ratio was settled by looking, not reasoning.** I recommended 4:3 and built
it (1.1 (79)); the owner's answer was *"i dont like it"*. 5:4 shipped in (80) and
stuck. **Two builds for one proportion is the cheap outcome** — the alternative
was shipping a shape nobody liked to every screen in the app.

## Where the list page ended up

Built on `PlaceView`'s structure, which was built on `TourDetailView`'s. Three
pages, one shape. Three differences are deliberate and documented in the file:
the carousel swipes the tours' own heroes (a list has no photographs), no GET
DIRECTIONS (a list is not anywhere), the map plots every tour (not one pin).

**Rows carry no position number.** Judgement call: the sequence already shows
order, the edit-mode arrows make it actionable, and a number column would push
the hero in and break the match with every other tour row in the app.

## The map extraction

`MakerView`'s map — camera, "Show all", stacked place cards — moved to
`Components/TourSetMap.swift`; both the maker page and the list page call it.
**The stacked cards are the load-bearing part**: a pin standing for two tours at
one coordinate can never be split by zooming, so without them one of those tours
is unreachable from the map. Copying that fix a third time is how the 14pt/16pt
pin drift happened.
