## 4. PR #458 — Journey → List

The UI already said "list"; the code still said Journey. Now both do.

| Was | Now |
|---|---|
| `Journey` | `TourList` |
| `JourneyItem` | `TourListItem` |
| `JourneyService` | `TourListService` |
| `Features/Journeys/` | `Features/Lists/` |
| `docs/journeys-design.md` | `docs/lists-design.md` |

Identifiers and comments only — 202 additions, 195 deletions, 16 files, no behaviour change.

**Not plain `List`.** SwiftUI's `List` is used in three views here; a same-named type makes every
`List { }` ambiguous and forces disambiguation at each site. `TourList` says what it holds.

### The Supabase tables are deliberately NOT renamed

They stay `journeys` / `journey_items` / `journey_id`, and `backend/journeys.sql` is untouched.
Renaming them needs a migration the owner runs by hand — and, the real reason, **every build already
on a tester's phone queries the old names.** They would break the moment the migration ran, for a
name no user ever sees. So every PostgREST string literal and `CodingKeys` raw value was left alone;
counts verified identical before and after: 7 × `journey_id`, 7 × `journey_items`, 5 × `journeys`.

### ⚠️ The trap in any Swift rename

A word-boundary search **cannot see `_journeyService`** — the property-wrapper storage for an
`@State`. Underscore is a word character, so `\bjourneyService\b` never matches it. It would have
failed to compile against the renamed property. Caught and fixed explicitly; the same applies to any
future `@State` / `@Binding` rename.

## Process notes worth carrying

- **CI ran on demand this session, and that is why the rename is trustworthy.** `workflow_dispatch`
  was added to `ci.yml` in session 74 after discovering that a web session's pushes to an open PR do
  **not** reliably fire `synchronize` — so only the commit that *opened* a PR ever got built, while
  the PR displayed green checks the whole time. For a rename, CI **is** the verification: a missed
  reference is a compile error, not a silent bug.
- **I over-scheduled check-ins.** One after every push, so four fired at once carrying stale notes.
  Only one build got cut (the workflow's concurrency guard caught the rest). Schedule a follow-up
  when there is something specific to wait for, not reflexively.
- **A shallow clone blocks branch comparison** (`git merge-base` → "no merge base"). Fix:
  `git fetch --unshallow --filter=blob:none` — keeps it cheap by skipping blobs.
- **Three sessions shared this date.** Check `ls archive/HANDOFF-*` before naming a handoff; `-2` and
  `-3` suffixes are normal.
