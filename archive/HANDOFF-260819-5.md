## 🔴 The bug worth carrying forward

**Opening a saved tour hung the app until the watchdog killed it (`0x8BADF00D`). Seven builds, six wrong diagnoses.** The cause was not in presentation, the toolbar, the dismiss guard, or our state writes. It was one line of my own code.

### The cause

`centerOnUser` opened with:

```swift
guard existingTourId == nil, ...   // deliberately skipped for a saved tour
```

So **creating** a tour handed the map a concrete `.region` in `onAppear`. **Editing** one left `cameraPosition == .automatic` while `centerCoordinate` was still nil — meaning no `MapCircle`, no annotations, **no content whatsoever** — until the fetched pin arrived. `Map(position:)` bound to `.automatic` with nothing to frame makes MapKit resolve a camera, write back through the binding, re-render, and resolve again: a synchronous layout loop with no terminating condition.

This is the only theory that ever explained **why creating a tour never hung**, which was the biggest clue available from day one and which I did not use until build 89 had eliminated everything else.

Fixed (build 90) by starting `cameraPosition` at a concrete fallback region and letting `centerOnUser` frame the camera on both paths. **Owner device-verified on TestFlight 1.1 (90).**

- **⚠️ The rule is `.automatic` OVER EMPTY CONTENT, not `.automatic`.** `TourSetMap` and the maker page's map both start `.automatic` and have never hung — they always have pins, so the frame resolves and settles. Do not "fix" them.
- **⚠️ On the edit path `centerOnUser` moves the CAMERA ONLY.** Writing the user's coordinate into `centerCoordinate` would invent an edit: it feeds `canPersist` and the change signature, so the tour would open already claiming unsaved work on a pin nobody placed.

### The falsification chain — six theories, do not re-walk it

| Build | Theory | Result |
|---|---|---|
| 81 | `DismissAttemptGuard` mutating `isModalInPresentation` | still hung |
| 84 | coordinate-write tolerance + cheap `interactiveDismissDisabled` | still hung |
| 87 | toolbar made structurally constant + footer height reserved | still hung |

| 89 | `.sheet` → `.fullScreenCover` | still hung — **ruled out presentation** |
| 90 | camera never `.automatic` over empty content | **fixed — owner-verified** |

Build 88 also falsified the whole "our state writes are the fuel" model: the wedge is a single synchronous runloop callout, inside which a `.task` cannot even begin to run.

### 🔴 The durable lesson

**A crash log is one sample of a spin.** Its top frames named a different function every time — `NavigationStack` body init (77), `ToolbarBridge.updateLocations()` (84), the Map's `PlatformViewChild` trait walk (87) — and I built a fix around each one. The `_sheetLayoutInfoLayout:` frames common to all of them were real but incidental: that is just where a synchronous relayout lands while a sheet is on screen.

**Diff the working path against the broken one before trusting any stack.** Create vs edit differed in one line, and finding it took five minutes once I looked.

### Kept although they were not the fix

All correct on their own terms: the `isEssentially` coordinate tolerance (`CLLocationCoordinate2D` has no `Equatable`); `.interactiveDismissDisabled` reading cheap state (it reconfigures the presentation controller); the toolbar + `NavigationStack` deletion (the wizard never navigates); one-batch loading after a settle; programmatic field fills guarded on `focused`.

**⚠️ The edit path is still `.fullScreenCover`** — shipped as a fix for a cause that proved wrong. Reverting to `.sheet` for visual consistency is reasonable, but as its own change from a verified-stable baseline.

### Process lessons, paid for in builds

- **When a fix fails, get the crash log for the build that failed.** Three builds were lost re-reading the build-77 log; its unsymbolicated `NavigationStack.init(root:)` frame was misread as the body under evaluation when it was the toolbar's host.
- `.ips` files: **Settings → Privacy & Security → Analytics & Improvements → Analytics Data**; trailing filename digits are `HHMMSS` local. A `.cpu_resource-*.ips` is a **sampled profile** — better than a crash log for a spin.
- Build numbers are `github.run_number`, shared across sessions — dispatches expecting 82 and 85 came back 84 and 87. **Read the number back.**

## Merging out — three things that only surface at the merge

- **The squash commit inherits the PR body.** #540's description was written before ten builds of change: it still said photo cap 8, called `TourAuthoringView` untouched (deleted), and did not mention the hang. Rewritten immediately before merging. **Do that at merge time, not at open time.**
- **Handoff filenames collide between parallel sessions.** `HANDOFF-260819-4.md` was claimed by another session for different work — an add/add conflict git cannot resolve. Theirs kept `-4`; this became `-5`. Check `archive/` for the next free suffix, and expect to renumber.
- **Merge `main` in and re-run CI before merging out.** One conflict was real code — main set `city: nil` with a comment saying maker tours carry no city, while this branch writes one (resolved `city: city, country: nil`). Main had also **deleted `AtlasSpacing.heroHeight`**; the tree was swept for references before committing. Taking either side wholesale would have shipped a wrong comment or a broken build.

## Process notes

- A CI build log carried **exactly one `error:` line in 95,219 characters** — grep the whole log, never tail it.
- **`Self` is rejected in a stored-property initializer** even on a `final class` ("covariant 'Self' type cannot be referenced from a stored property initializer") — use the type's own name.
- The **job-status API lags**: a job reporting `in_progress` had already written `** TEST SUCCEEDED **` to its log.
- A CI unit-test job hung past 20 minutes with no downloadable logs; the documented **cancel-and-rerun** cleared it and the same job then finished in 3 minutes.
- **Build numbers are `github.run_number` and shared across every session** — this build was dispatched expecting 82 and came back **84**. Read the number back after dispatching; never promise it in advance.
