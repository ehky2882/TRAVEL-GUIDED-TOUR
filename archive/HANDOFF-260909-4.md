## Why the token is trustworthy — the part worth keeping

`payload` and `refreshed_at` are **two columns of the same single row** in
`public.catalog_snapshot`, written by one `insert … on conflict do update` inside
`refresh_catalog_snapshot()`.

The dangerous failure for any "has it changed?" scheme is a version that says **no** when the
answer is **yes**: every phone quietly freezes on old content and nothing errors anywhere. That is
the exact shape of the 2026-08-19 incident, where three features vanished for 14 hours because a
missing key decoded as `nil` rather than as a failure.

**Here that is structurally unreachable rather than merely guarded against** — the version *is*
the content's own row. It can only be wrong in the harmless direction: a re-seed that changed
nothing still moves the timestamp, so we download unnecessarily.

The other half of the safety argument is the rule that everything **fails toward downloading**. A
probe that errors, times out, returns non-2xx, an empty body, `null`, or anything oversized yields
no token, and the download proceeds as before.

## 🔴 Two bugs the design doc did not anticipate — found while building

Both are the same class: **a cheap check quietly becoming the reason correct content does not
arrive.** Both are now written into the design doc so the reasoning survives with the code.

**1. "Up to date" has to STOP the source chain, not just skip one fetch.** The loader tries
Supabase and then falls through to the gh-pages mirror. Had the version check merely reported "no
catalogue from this source", the loop would have fallen through and **downloaded the whole 3.4 MB
mirror to learn what it already knew** — the saving would have been exactly zero, and every test
of the Supabase path alone would still have passed. A source now resolves to `fetched` /
`upToDate` / `unusable`, and `upToDate` returns immediately. Guarded by
`test_refresh_skipsMirror_whenSupabaseSaysWeAreCurrent`.

**2. A cache written from the mirror must CLEAR the stored token, not leave it.** If Supabase is
down and the cache is rewritten from gh-pages, a leftover Supabase token would sit beside content
it did not come from. The next probe could match that token and **pin the app to the mirror's copy
indefinitely** — silent staleness arriving by the back door. `writeCache(_:catalogVersion:)`
therefore *removes* the sidecar when the source has no version to give. Guarded by
`test_refresh_fallsBackToMirror_andClearsStoredVersion_whenSupabaseIsDown`.

**One ordering detail that matters:** the token is stamped only on bytes that actually decoded,
and it is the token read **before** the download. A snapshot rebuilt mid-download therefore leaves
us one version *behind* (we re-download next time), never one *ahead* (we would never download
again).

## What this does NOT fix

**When anything has changed — even one tour — the app still downloads all 1,552 tours.** This cuts
how *often* we pay, not how *much*.

The next step, already scoped and explicitly deferred rather than cancelled, is **Option B:
dropping `stops.transcriptText` (38% of the payload) and `longDescription` (18%)** — both sent for
every tour on every fetch, both visible only on one tour's own page. That is a **breaking**
catalogue change and needs its own thinking about builds already on phones.
