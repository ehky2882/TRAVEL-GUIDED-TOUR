## ⚠️ Open item for Phase 3 — the JWT gate

The Supabase toggle reads *"Verify JWT with **legacy secret**"*, but this project signs user tokens with **ES256** (`/auth/v1/.well-known/jwks.json` returns an EC key; `SUPABASE_ANON_KEY` is flagged DEPRECATED in the secrets list). Whether a genuine signed-in user's token satisfies a gate described as *legacy* cannot be tested until a logged-in user exists — i.e. Phase 3.

- **If Phase 3 purchases come back 401:** verify the JWT against the JWKS **inside** `record-purchase`, then turn the toggle OFF.
- **Do NOT turn it off first.** `record-purchase` currently decodes `sub` without verifying and leans on the gateway; switching the gate off before adding in-function verification would let any caller claim any buyer identity.
- **Functionality** risk, not a live hole. Flagged rather than guessed.
