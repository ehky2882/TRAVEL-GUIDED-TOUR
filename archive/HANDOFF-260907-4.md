## 2. 🔴 One post, three pins — the `@malata.antwerp` shape, second instance ever

`DWHSGzlEZSv` is a single `@rayisaplace` post about **Peter Zumthor**, naming four of his
works; the owner supplied three separate Plus Codes for it. That is the documented
one-post-many-pins case (five malata pins from one *Top 5 Italian antique markets* video),
and it needs the fragment id scheme, which nothing writes down — **it was reverse-engineered
from the live catalogue again**:

```
atlas-tour:link:<sourceURL>#<fragment>      uuid5(NAMESPACE_URL, …), uppercase
atlas-stop:link:<sourceURL>#<fragment>
```

Verified by reproducing **4 of the 5 live malata pins field-for-field on both the tour id and
the stop id** before minting anything. Fragments used here: `#los-angeles` · `#vals` ·
`#mechernich`.

**The three pins share ONE hero file**, as the malata five do — so **35 files cover 37 pins**,
and a naive `len(files) == len(pins)` assertion would fail. The file is deliberately named
**`peter-zumthor-rayisaplace_hero.webp`**, not a LACMA-specific stem, because it serves all
three.

⚠️ **The cost is stated rather than hidden:** the frame is the LACMA underside, so someone
standing at Therme Vals or the Bruder Klaus chapel gets a pin whose photograph is Los
Angeles. Exactly the Charging Bull / Greenpoint-foundry trade-off. **One line removes any of
the three.**

## 3. 🔴 Two reference geocodes were wrong, and both were caught before use

Short Plus Codes recover against a reference point, so a wrong reference silently moves the
pin to another country.

| Query | What it matched | Fix |
|---|---|---|
| `Chuo City Tokyo` | **`Tokyo Rokumeikan`, a confectionery in Chuo-ku OSAKA** | structured `city=Chuo&state=Tokyo&country=Japan` |
| `Venice Italy` | **`Venice-Italy`, a restaurant in GRAZ, AUSTRIA** | structured `city=Venezia&country=Italy` |

**Use the structured Nominatim parameters for a short-code reference, never a free-text
string.** Both would have produced a confident, precisely-decoded, entirely wrong coordinate.
