## The flow, and what it actually caught

The owner supplied 21 TikTok share links, each with a Google Plus Code or a rough address instead
of coordinates. The full flow:

1. **oEmbed** on every URL (`https://www.tiktok.com/oembed?url=…`) to pull each post's caption —
   no auth needed, and it's how the whole batch turned out to share one creator.
2. **Plus Codes decoded** with `scripts/decode-plus-code.py` (hand-rolled, `pip install
   openlocationcode` can't build a wheel in this container). `--selftest` green before trusting
   any output — it's bitten before (Hong Kong codes landing in Thailand on a bad rebuild).
   Short codes (`PXMW+QW New York`, `3J7Q+89 Los Angeles`) were recovered against a city-centre
   reference; full codes decoded directly.
3. **Reverse-geocoded** via Nominatim (`nominatim.openstreetmap.org/reverse`, rate-limited to
   ~1 req/s — hit 429 on a few and retried after a cooldown).
4. **🔴 The reverse-geocode alone was not enough, and the post's own thumbnail is what caught it.**
   Several of `@nickcabotrodriguez`'s thumbnails burn the real subject name or exact street
   address into the frame — reading them directly corrected a handful of my geocoded first
   guesses before any pin was minted:
   - A pin I'd labelled "a Hollywood building on Wilcox Avenue" (nearest OSM name: a sushi
     restaurant) is actually the **Hollywood Pacific Theatre**.
   - "A boarded-up West Village building" (nearest OSM name: a rec centre) is the **Tony Dapolito
     Recreation Center**'s own building.
   - "A Madison Avenue restaurant" is **E.A.T.**; "a 1980s Upper West Side restaurant" is
     **Cafe Luxembourg**.
   - Several address-only titles (50 West 13th St., 565 West 23rd St., 31 Canal St., 36 Greene
     St., 44 West 73rd St., 124 East 80th St., 34 East 12th St.) matched the thumbnail's own
     burned-in address exactly, which is the strongest confirmation available for a subject with
     no public name.
   Coordinates and the proposed subject/category/tags were read back to the owner before minting
   anything, per their request.
5. **Minted individually**, not batched — `make-link-pin.py --batch` only applies `--title`/
   `--slug` when the batch is a single line, and this creator's captions are a repeated house
   format ("What's up with this building? Part N #hashtags…") that is not the subject's name.
   21 separate `--url` calls kept each pin's real title and hero filename correct.

## The tag decision

The owner asked to add all 21 using **only the existing controlled vocabulary**, holding an
"Abandoned" tag idea for later. 12 of the 21 subjects are visibly abandoned/vacant and would use
it, but `Tag.swift`'s vocabulary (mirrored in `scripts/seed_tags.py` and
`docs/tag-taxonomy-v2.md`) has no such tag today, and adding one is a Swift model change — this
repo's rule is that waits for the owner, not a content contributor. So this batch ships with the
nearest existing tags (`Notable Building`, `History`, etc.) and nothing was added to the
vocabulary.
