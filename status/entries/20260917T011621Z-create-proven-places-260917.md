# Six proven places created, and the place-id formula finally written down

_2026-09-17 01:16 UTC · branch `create-proven-places-260917`_

**The place-id formula is found and written down.** It was in
`archive/CURRENT-STATE-HISTORY.md`, the file `CLAUDE.md` tells every session to
*search, never load whole* — so nobody found it. This session brute-forced a
dozen key shapes, failed, and was one step from inventing a second scheme.

```
uuid5(NAMESPACE_URL, f"atlas-place:{slug(city)}:{slug(name)}")
```

**Verified: 339 of 344 existing ids.** The five misses are places renamed after
minting. ⚠️ `slug` **drops** non-ASCII rather than transliterating —
`Sagrada Família` → `sagrada-fam-lia`. Transliterating scores 320/344, so the
odd-looking behaviour is the real one. Now in `docs/places.md`.

**Six places created**, each coincident AND independently proven one venue:
Peter Pan Donut & Pastry Shop, Pecking House, Mark's Off Madison, Round Swamp
Farm, Hawksmoor NYC, House of Prime Rib. Places 344 → 350. EXACT·PROVEN falls
14 → 8, NAME 4 → 2.

🔴 **Seven were NOT created, deliberately.** They are provably one venue but
have **no readable venue name** — every title is a caption
(*"Did I squeeze this too hard?? 📍@eatnamkeen"*). Naming a place from a handle
is a guess, and a wrong name is visible to every user. `@eatlittlekirin`,
`@lindustriebk`, `@paninishoppe`, `@eatnamkeen`, `@allanticovinaionyc`,
`@soothr_nyc`, `@redhooklobster` — these need the owner or brother to say what
each venue is called.

⚠️ `description` and `heroImageURL` left **null** on all six rather than
invented. That is normal — 14 of 344 places carry no description and 177 no hero
image — and inventing prose about a restaurant nobody in this session has been
to is the one thing worse than a blank field.
