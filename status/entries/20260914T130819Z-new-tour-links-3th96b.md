# Supabase back: cause was t4g.nano compute, not egress

_2026-09-14 13:08 UTC · branch `new-tour-links-3th96b`_

**Supabase recovered at 13:01 UTC after ~11h45m down, and the cause was not what
two sessions thought.**

The instance was **`t4g.nano` — 512 MB RAM, shared CPU** — memory at 79%, and
`get_catalog` builds the whole catalogue in memory on every call. Fixed by moving
compute to **Micro**, which is **the same $0.01344/hour** and which Supabase
itself labels a free upgrade: 1 GB and a dedicated 2-core CPU.

🔴 **The egress-restriction theory was wrong.** The owner had been on Pro since
**10 September**, four days before the outage, so the grace period that ended on
the 13th never applied. Two sessions inferred it from the dates and neither asked.
🔴 **Pro raises egress, not compute** — that is why the upgrade did not prevent
this. Written up in `docs/lessons.md` § 6.
