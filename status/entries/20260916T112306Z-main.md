# 65 link pins: @ninosbuildings triaged, geocoded, merged (#940)

_2026-09-16 11:23 UTC · branch `main`_

Owner handed a pile of 69 TikTok links from one creator (@ninosbuildings), most with
generic engagement-bait captions carrying no place name. Triaged via oEmbed captions +
visual identification of the video thumbnail against known landmarks (the owner's hint
that "the video subtitle gives hints" held — several thumbnails had the reveal text
burned in, e.g. Bosco Verticale's architect name). 37 of 69 identified with confidence
from the video alone; reported the rest as needing owner input, split by SKIP (no
landmark visible) vs NEEDS RESEARCH (a lead but unconfirmed).

Owner reviewed and supplied exact addresses for 27 more, plus split one "two towers"
Singapore post into two separate pins (Beverly Mai + The Concourse) — leaving only 1
of 69 posts genuinely unpinnable (a private home interior, no location given).

Geocoded every address via Nominatim (~1 req/2s, several retries needed — some named
queries 404'd until reformatted as plain street addresses). Minted all 65 via a
one-off driver script that calls `make_one()` directly (bypassing `make-link-pin.py`'s
CLI, which only accepts one `--category`/`--tags` per whole batch run) so each pin
could carry building-specific tags. Caught two URL-transcription bugs before minting
by cross-checking every row against the authoritative caption table — Lloyd's Building
and Rosewood São Paulo had been paired with the wrong source post.

Hand-computed the two-pins-from-one-post fragment ids for the Singapore pair per
docs/link-pin-runbook.md — `merge-link-pins.py --check` confirmed both reproduce
from the documented uuid5 scheme, hashed against the CANONICAL sourceURL (not my
short vm.tiktok.com link — the first attempt used the wrong string and was refused).

gh-pages heroes uploaded via git plumbing (`gh` unavailable), one commit, additions
only. Hash-verified all 65 live URLs against local bytes after Pages caught up
(~10 min lag, as documented). `validate-tours-mirror.py`: 0 errors. `check-image-
duplicates.py --pins`: only byte-identical pair is the deliberate Beverly Mai/
Concourse share; no collisions with the rest of the catalog.

PR #940, CI green (unit tests, Tours.json validation, sim build all passed), no
merge conflict, squash-merged. linkPins 2356 → 2421, makers unchanged (creator
already had 4 earlier pins). Left CLAUDE.md's Key-facts paragraph untouched —
several other sessions' PRs (#931-#939) landed during this one alone, so a hand
edit there would have been stale before this entry was even written.
