_2026-09-15 14:12 UTC · branch `board-912-merged`_

🟢 **`get_catalog_since` is LIVE in production** — owner pasted `backend/catalog_since.sql`
2026-09-15 ~14:1x UTC. The owner item is cleared (deleted, per Rule 10).

**Measured against the live RPC, cheaply (never pulled the full catalogue):**

| cursor | bytes | rows |
|---|---:|---|
| `since(head)` — nothing changed | **128** | 0 |
| `since(9300)` | **3,654** | 5 pins |
| `since(9200)` and below | 43,476 | 103 pins |
| *(full `get_catalog` for comparison)* | *2,427,222* | *everything* |

**128 bytes against 2,427,222 — about 19,000× smaller** on the common "nothing changed" call, and
**56× smaller** for a 103-row change.

🔴 **The anti-drift design is CONFIRMED ON PRODUCTION DATA, not just a fixture.** A delta pin comes
back with **24 keys, every non-optional `Tour` property present** — and **`stops[].transcriptText`
is ABSENT**. Nothing in `catalog_since.sql` excludes that field. It is absent because the
*snapshot* does not carry it (#795 dropped it for egress on 2026-09-10), and the delta returns the
snapshot's own elements byte for byte. That is the "one shaper, not two" guarantee holding against
real data: a field removed months ago stays removed, with no second copy of the shaping logic to
keep in step.

Envelope carries all seven keys: `tours`, `linkPins`, `makers`, `places`, `removedIds`, `rev`,
`refreshedAt`.

⚠️ **Nothing changes for users yet** — [#914](https://github.com/ehky2882/TRAVEL-GUIDED-TOUR/pull/914)
is the client half and is unmerged. The RPC being live is what makes #914's device check
*meaningful*: before this, the delta path was dormant and any on-device test passed trivially.

⚠️ **`check-catalog-contract.py` deliberately NOT run.** Rule 11 aims it at SQL touching
`get_catalog`; this migration adds two functions and redefines nothing in that chain. Running it
would pull the full 2.4 MB, which is precisely what this work exists to stop.
