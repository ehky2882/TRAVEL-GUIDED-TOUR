_2026-09-13 15:57 UTC · branch `main`_

A new contributor (`arthuryung-gif`) joined this week to add content. Two things shipped for that, plus his first batch.

**Onboarding (#763, merged 2026-09-08).** `docs/partner-onboarding.md` is the zero-to-first-upload guide for someone who has never used a terminal; `.claude/skills/atlas-upload/SKILL.md` is the repo's first project skill, loaded by saying *"use the atlas-upload skill"*, so nothing installs on his side. **His first batch (#787, merged).** 20 link pins across France, the Netherlands, Japan, Sweden, Denmark and the UK. His session minted them but could not fetch a single thumbnail, so this session regenerated the 20 heroes from his `pins.tsv` and pushed them to gh-pages (`944433f7`). Verified: filenames match the catalog exactly, 20 distinct images all 1200×900, no collision with the 7,484 live files, tree diff of 20 additions and nothing else, then all 20 URLs live and byte-identical once Pages finished. Zero duplicate posts against `main`. Confirmed live in `get_catalog` afterwards.

**The cause, now documented (#852, merged).** A cloud environment starts on the **Trusted** network access level — package registries and GitHub, nothing else — while the pin pipeline needs `tiktok.com`, `instagram.com` and `ehky2882.github.io`. GitHub being reachable is what makes it dangerous: the batch dies HALF DONE with `Tours.json` pointing at heroes nobody uploaded, which `validate-tours.swift` passes because the URLs are well-formed and it never fetches them. Fix is the environment, not the code: claude.ai/code → cloud icon → settings → Network access **Trusted → Full**, then a NEW session.

⚠️ **Three traps found the same day, all in `docs/lessons.md` now.** Pillow is often absent and without it `make-link-pin.py --selftest` reports **62/62, which reads as a pass**, against 71/71. `gh` may be absent too — and the obvious workaround nearly wiped live images: gh-pages is ~4 GB, a checkout killed partway leaves a tree where `git add` stages **thousands of deletions**, caught only by reading the tree diff before pushing. Build that commit with plumbing instead. And `check-image-duplicates.py --pins` printed `OK` having 404'd on every new hero, because a Pages deploy takes ~10 minutes.

⚠️ **Unexplained, for whoever picks it up:** the live RPC reported **1,972 link pins and 290 places** where `main`'s `Tours.json` had **1,635 and 141**. Upsert-only seeding explains a superset, but not obviously a gap that size. Assert on specific pins, never on totals, until someone diffs it properly.
