🔴 **THIS BUILD SHOWS NOTHING UNTIL #915 MERGES — and the reason is the
session-95 trap, which this note got wrong on its first draft.**
`RemoteCatalogLoader` tries **Supabase first** and takes the first source that
decodes; the bundled `Tours.json` is a fallback that a phone with signal never
reaches. Supabase currently serves both new keys as `null` (the columns exist
and are empty until a re-seed), so on this binary the More Like This section is
**absent everywhere** and the date sorts are still inert. The branch's own
catalogue does carry the data and is irrelevant to what the phone reads.

**So the order is: merge #915 → `publish-catalog.yml` seeds Supabase and
refreshes the snapshot → this same build 162 picks the data up over the air on
next launch.** No rebuild is needed.

⚠️ That means the device check happens AFTER the merge, which inverts the
usual gate for a code PR. What makes it acceptable: the section is additive and
**data-gated** — `relatedTourIds` nil means it does not render at all — so
clearing the key in the catalogue turns the whole feature off with a content
edit and no app release.

**Device check:** a dense city (London, New York) and a thin one (San
Francisco, Naoshima); no tour repeated across "Also at ...", "Nearby Tours" and
"More Like This"; the section absent on the two tours with no neighbours
